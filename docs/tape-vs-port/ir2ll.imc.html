1#THIS IS FILE IR2LL, THE LLVM IR WRITER: THE TRANSLATION OF TOOLS/IR2LL.C (WHICH THE SEED KEEPS) INTO IMP, SO THAT NO C IS LEFT IN IT BUT THE SHIM STAGE0/IR2LL_SHIM.C THAT STAGE0/LLVMORC.C CALLS. NOT IN THE TAPE: THE ORIGINAL'S OMOD
2 WRITES PDP-10 OBJECT CODE. IR2LLRUN(INF,OUTF,PTR32) READS THE TEXT OF THE IR THAT THE CODE GENERATOR WRITES (SRC/IX.IMC: "* TEXT" LINES, "! TYPE FLAGS PROLAB TMPBASE LBLBASE NAME", "^ N", '" OP TYPE QUAL ...' ONE TREE NODE A LINE, PREORDER,
3 AND "% AUTOS RETLAB TMPEND LBLEND NAME") FROM THE FILE INF AND WRITES THE MODULE OF LLVM IR AS TEXT TO THE FILE OUTF; PTR32 IS 1 WHEN THE HOST'S POINTERS ARE 32 BITS. IT RETURNS 0. THE TEXT IS THE C'S BYTE FOR BYTE. THE CODE GENERATOR OF THIS COMPILER CAN NAME ONLY 2047 REGISTERS IN A COMPILATION (AREG1 IN SRC/IMPSEM.IMC: THE INDEX IS 11 BITS IN THE RECORDS), SO THE WRITER IS IN TWO FILES: THIS ONE HAS
4 THE ENTRY, THE READING AND THE DATA, AND SRC/IR2LLX.IMC THE EXPRESSIONS AND THE STATEMENTS. WHAT THEY SHARE IS COMMON, DECLARED THE SAME IN BOTH (THE IMAGE LEAVES ALL OF IT OUT: IMGSKIP IN SRC/IMAGE.IMC).
5 A NODE IS EIGHT WORDS (OP, TYPE, VALUE, REGISTER OR TEMP NUMBER, NAME, LEFT, RIGHT; THE FIELDS ARE [N]..[N+6]: A BRACKET WITH A LITERAL INDEX COUNTS WORDS). THE TEXT IS BUILT IN BUFFERS OF OUR OWN (IRLPC, IRLPS, IRLPN:
6 THE C LIBRARY'S OPEN_MEMSTREAM HAS AN UNDERSCORE, AND A NUMBER IS WRITTEN WITHOUT A CALL THAT TAKES A 64 BIT VALUE, AS IN IX.IMC); THE NODES AND THE STRINGS OF A FUNCTION ARE IN AN ARENA THAT IS GIVEN BACK AT ITS END.
7 THE ROUTINES THAT CALL ONE ANOTHER WITHOUT END (THE EXPRESSIONS: IRLEXPR, IRLEXC, IRLLOAD, IRLPLACE, IRLSTORE, IRLCOMPARE, IRLCALLEXPR, AND IRLREAD AND IRLNOTE FOR THE TREES) KEEP NOTHING IN THEIR VARIABLES ACROSS A CALL (A VARIABLE IS ONE WORD
