128WE NOW DESCRIBE EACH TYPE OF STACK ENTRY INDIVIDUALLY. THE ARITHMETIC TYPE
129 FIELD APPLIES TO EACH TYPE OF NODE, AND WILL NOT BE MENTIONED FURTHER HERE.
130 EVERY ONE OF THESE TYPES MAY HAVE CODE ASSOCIATED WITH IT.
132TYPE 2 (REGISTER): ALL FIELDS EXCEPT REG ARE IGNORED. THIS ENTRY IS TALKING
133 ABOUT THE NUMBER IN A REGISTER AND NOTHING BUT.
134TYPE 4 (CONSTANT): ALL FIELDS BUT VAL AND DIR ARE IGNORED. FURTHERMORE, IF
135 DIR IS NONZERO, IT IS ALWAYS THE DIRECTORY INDEX OF SOME IDENTIFIER WHICH
136 IS A CONSTANT WITH VALUE EQUAL TO THE VAL FIELD. (IF THE CONSTANT IS
137 MULTIWORD, THE VAL FIELD IS THE VALUE OF THE FIRST WORD.)
138TYPE 10 (NAME): ALL FIELDS BUT DIR AND CONST ARE IGNORED. DIR (IF NONZERO)
139 IS THE DIR INDEX OF SOME IDENTIFIER WHICH WILL WIND UP AS A TAG OR SOMETHING
140 ELSE WITH AN ADDRESS. THIS NODE IS TALKING ABOUT THE VALUE OF THE MEMORY
141 LOCATION AT DIR+CON.
142TYPE 20 (MEMORY): THIS ONE IS THE HAIRY BRUTE. ALL FIELDS (EXCEPT VAL, WHICH
143 IS ONLY FOR CONSTANTS) SWING INTO ACTION. THIS NODE IS TALKING ABOUT ANY
144 WORD WHOSE ADDRESS CANNOT BE COMPILED INTO AN ADDRESS FIELD AT COMPILE TIME.
145 EXAMPLES: VARIABLES WITH NON-CONSTANT SUBSCRIPTS, AND SUBROUTINE PARAMETERS.
146 THE DI+CON, REG, AND INDIRECT BIT ARE STUFFED INTO THE ADDRESS PORTION OF A
147 PDP-10 INSTRUCTION WORD, AND VOILA. THIS IS THE ONLY TYPE OF STACK ENTRY
148 WHICH MAY HAVE THE INDIRECT BIT SET.
150THE ROUTINES DEWOP(OP,REG,S), ADDOP(OP,S,T), AND STORE(S,T)
151 HAVE A BIT MORE MACHINE-DEPENDANT "SMARTS" THAN
152 ONE MIGHT EXPECT, AND THE READER WHO PLANS TO WRITE SEMANTICS ON THE
153 INSTRUCTION-GENERATING LEVEL WILL SAVE HIMSELF A LOT OF WORK BY TAKING NOTE
154 OF THEM.
155DEWOP TAKES A 9-BIT OPCODE OP, A REGISTER INDEX REG (REG=0=>NO ACCUMULATOR),
156 AND A STACK ENTRY S. IT ADDS TO S THE INSTRUCTION CONSTRUCTED BY INSERTING
157 OP AND REG AS THE OPCODE AND ACCUMULATOR, AND GETTING THE INDEX REGISTER,
158 INDIRECT BIT, AND ADDRESS FROM S. IT ASSUMES THAT THE RESULT OF THE INSTRUC-
159 TION WINDS UP IN REG, SO IF REG IS NONZERO IT CHANGES THE TYPE OF S TO 2.
160 OTHER THAN THAT, THE FIELDS OF S ARE NOT CHANGED.
161IF S IS OF TYPE 2 TO BEGIN WITH, THE ADDRESS FIELD OF THE INSTRUCTION GETS THE
162 REGISTER NUMBER - THE REGISTER IS TREATED AS A MEMORY LOCATION.
163IF S IS OF TYPE 4, DEWOP CHECKS TO SEE IF THE CONSTANT IS IN THE RIGHT 18 BITS,
164 AND IF THE OPCODE HAS AN IMMEDIATE MODE. IF SO, AN IMMEDIATE INSTRUCTION IS
165 GENERATED. IF NOT, A CHECK IS MADE TO SEE IF THE CONSTANT HAS A DIR INDEX.
166 IF NOT, AN IDENTIFIER IS CREATED FOR IT SO THAT ITS ADDRESS CAN BE REFERRED
167 TO BY THE INSTRUCTION.
169FETCH(S) GETS S INTO A REGISTER. IT CALLS DEWOP(200B,REG,S) TO DO SO UNLESS
170 S IS A CONSTANT, IN WHICH CASE IT MAY USE ANY OF A NUMBER OF HALF-WORD
171 INSTRUCTIONS.
172STORE(S,T) GETS T INTO S, WHICH OUGHT NOT TO BE OF TYPE 4. IT HOOKS ON THE
173 CODE FOR T BEFORE THAT OF S. IT DOES THE JOB BY CALLING DEWOP(202B,REG,S)
174 IN MOST CASES. HOWEVER, IF S IS OF TYPE 10 OR 20 WITH NO ASSOCIATED CODE,
175 AND THE LAST INSTRUCTION IN T'S CODE REFERENCES S, STORE ALTERS THE INSTRUC-
176 TION TO DO A SELF OR BOTH OPERATION IF POSSIBLE.
177ADDOP(OP,S,T) IS HOOK(S,T,DEWOP(OP,REGOF(FETCH(T)),S)), WHICH PERFORMS THE
178 BINARY OPERATION OP ON S AND T. THIS COULD BE WRITTEN EXPLICITLY IN
179 SEMANTICS, BUT WAS DEFINED AS A ROUTINE TO SAVE WRITING THE SAME THING
180 MANY TIMES. ADDOP, NATURALLY, HAS ALL THE SMARTS OF DEWOP.
